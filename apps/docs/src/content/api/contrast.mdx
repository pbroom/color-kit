# Contrast

<p className="docs-lede">
  WCAG 2.1 and APCA contrast measurement for `Color` values, plus
  contrast-region geometry helpers that trace threshold contours in
  lightness/chroma space at a fixed hue.
</p>

<div className="prose-api">

## Shared Notes

- All functions take the internal `Color` representation (OKLCH: `l` in `[0, 1]`, `c` in `[0, ~0.4]`, `h` in degrees, `alpha` in `[0, 1]`).
- Scalar helpers (`relativeLuminance`, `contrastRatio`, `contrastAPCA`, `meetsAA`, `meetsAAA`) measure the color's **unrounded** sRGB channels, clipped to the display gamut. Results are continuous in the color and match colorjs.io for in-gamut colors. For 8-bit (hex) inputs they agree with byte-based tools to float precision.
- Every scalar helper takes an optional `ContrastOptions` object as its last argument:
  - `gamut` (`'srgb' | 'display-p3'`, default `'srgb'`) is the display gamut to clip to before measuring. Use `'display-p3'` to check colors shown on a P3 display.
  - `precision` (`'exact' | '8bit'`, default `'exact'`) controls rounding. `'8bit'` quantizes the channels to 8 bits first, matching hex-based tools such as WebAIM and the color-kit 0.1 results.
- `contrastAPCA` returns a **normalized** Lc value (roughly `-1.08` to `1.06`), not the conventional `-108`–`106` scale. Thresholds elsewhere in Color Kit (for example `apcaPreset`) use the same normalized scale: conventional Lc 60 is `0.6`.
- The region helpers use the same measurement as the scalar helpers, with the region's `gamut`. A color inside a `gamut: 'display-p3'` region passes `contrastRatio(color, reference, { gamut: 'display-p3' })`.

## `relativeLuminance`

Calculates relative luminance per [WCAG 2.1](https://www.w3.org/TR/WCAG21/#dfn-relative-luminance). The color is converted to linear sRGB and clipped to the gamut, without rounding. The result is the weighted sum `0.2126 R + 0.7152 G + 0.0722 B`.

```ts
import { parse, relativeLuminance } from 'color-kit';

const y = relativeLuminance(parse('#3b82f6'));
// ~0.21
```

| Parameter | Type              | Default | Description                         |
| --------- | ----------------- | ------- | ----------------------------------- |
| `color`   | `Color`           | —       | Color to measure                    |
| `options` | `ContrastOptions` | —       | `gamut` and `precision` (see above) |

<p className="api-returns">
  Returns a <code>number</code> in `[0, 1]` (0 = black, 1 = white).
</p>

## `contrastRatio`

Calculates the [WCAG 2.1 contrast ratio](https://www.w3.org/TR/WCAG21/#dfn-contrast-ratio) between two colors: `(lighter + 0.05) / (darker + 0.05)` using their relative luminances. Argument order does not matter.

```ts
import { contrastRatio, parse } from 'color-kit';

const ratio = contrastRatio(parse('#111827'), parse('#ffffff'));
// ~17.7
```

| Parameter | Type              | Default | Description                         |
| --------- | ----------------- | ------- | ----------------------------------- |
| `color1`  | `Color`           | —       | First color                         |
| `color2`  | `Color`           | —       | Second color                        |
| `options` | `ContrastOptions` | —       | `gamut` and `precision` (see above) |

<p className="api-returns">
  Returns a <code>number</code> between 1 and 21.
</p>

## `meetsAA`

Checks whether two colors meet the WCAG AA contrast requirement. Normal text requires a ratio of at least `4.5:1`; pass `largeText: true` to use the large-text threshold of `3:1`.

```ts
import { meetsAA, parse } from 'color-kit';

meetsAA(parse('#6b7280'), parse('#ffffff')); // false (4.5:1 required)
meetsAA(parse('#6b7280'), parse('#ffffff'), true); // true (3:1 required)
```

| Parameter   | Type              | Default | Description                          |
| ----------- | ----------------- | ------- | ------------------------------------ |
| `color1`    | `Color`           | —       | First color                          |
| `color2`    | `Color`           | —       | Second color                         |
| `largeText` | `boolean`         | `false` | Use the large-text threshold (`3:1`) |
| `options`   | `ContrastOptions` | —       | `gamut` and `precision` (see above)  |

<p className="api-returns">
  Returns a <code>boolean</code>.
</p>

## `meetsAAA`

Checks whether two colors meet the WCAG AAA contrast requirement. Normal text requires a ratio of at least `7:1`; pass `largeText: true` to use the large-text threshold of `4.5:1`.

```ts
import { meetsAAA, parse } from 'color-kit';

meetsAAA(parse('#111827'), parse('#ffffff')); // true
```

| Parameter   | Type              | Default | Description                            |
| ----------- | ----------------- | ------- | -------------------------------------- |
| `color1`    | `Color`           | —       | First color                            |
| `color2`    | `Color`           | —       | Second color                           |
| `largeText` | `boolean`         | `false` | Use the large-text threshold (`4.5:1`) |
| `options`   | `ContrastOptions` | —       | `gamut` and `precision` (see above)    |

<p className="api-returns">
  Returns a <code>boolean</code>.
</p>

## `contrastAPCA`

Calculates APCA (Advanced Perceptual Contrast Algorithm) contrast, based on APCA-W3 0.0.98G-4g. Unlike `contrastRatio`, APCA is polarity-aware — the argument order matters:

- Positive Lc &mdash; dark text on a light background (normal polarity).
- Negative Lc &mdash; light text on a dark background (reverse polarity).
- Values with magnitude below the low clip (`0.1` normalized) return `0`.

```ts
import { contrastAPCA, parse } from 'color-kit';

const lc = contrastAPCA(parse('#111827'), parse('#ffffff'));
// positive ~0.9+ (dark text on light background)

const reversed = contrastAPCA(parse('#ffffff'), parse('#111827'));
// negative (light text on dark background)
```

| Parameter   | Type              | Default | Description                         |
| ----------- | ----------------- | ------- | ----------------------------------- |
| `textColor` | `Color`           | —       | Foreground color                    |
| `bgColor`   | `Color`           | —       | Background color                    |
| `options`   | `ContrastOptions` | —       | `gamut` and `precision` (see above) |

<p className="api-returns">
  Returns a normalized Lc <code>number</code>, roughly between `-1.08` and
  `1.06`. Multiply by 100 for the conventional APCA scale.
</p>

## Contrast Region Geometry

`contrastRegionPaths` and `contrastRegionPath` trace the contour of the region where colors at a fixed hue meet a contrast criterion against a reference color. Points are expressed in lightness/chroma coordinates (`{ l, c }`), ready to project onto an LC plane.

For the plane-integrated variants that return viewport-aware, plane-space results (`contrastBoundary`, `contrastRegion`), see [Plane Queries](/docs/api/plane-queries).

## `contrastRegionPaths`

Generates contour paths for the region that meets or exceeds the configured contrast criterion at a fixed hue. Each side of the region (darker or lighter than the reference) is one luminance level curve; the solver traces it along rays from black and solves exactly where each piece meets the gamut edge.

```ts
import { contrastRegionPaths, parse } from 'color-kit';

const paths = contrastRegionPaths(parse('#ffffff'), 220, {
  metric: 'wcag',
  level: 'AA',
  gamut: 'srgb',
  simplifyTolerance: 0.001,
});
```

| Parameter   | Type                                   | Default | Description                                                              |
| ----------- | -------------------------------------- | ------- | ------------------------------------------------------------------------ |
| `reference` | `Color`                                | —       | Reference color, measured as displayed in the target gamut (see `gamut`) |
| `hue`       | `number`                               | —       | Fixed hue angle in degrees                                               |
| `options`   | `ContrastRegionPathOptions` (optional) | `{}`    | Criterion and solver options (see below)                                 |

<p className="api-returns">
  Returns <code>{'ContrastRegionPoint[][]'}</code> &mdash; contour paths of{' '}
  <code>{'{ l, c }'}</code> points, sorted longest first.
</p>

### Criterion options

| Option         | Type                                     | Default         | Description                                                                                                                              |
| -------------- | ---------------------------------------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `metric`       | `'wcag' \| 'apca'`                       | `'wcag'`        | Contrast metric used when evaluating region membership                                                                                   |
| `threshold`    | `number`                                 | from preset     | Explicit threshold; overrides `level` / `apcaPreset`. For `wcag` a ratio (must be `> 1`); for `apca` a normalized Lc (must be `> 0`)     |
| `level`        | `'AA' \| 'AAA' \| 'AA-large'`            | `'AA'`          | WCAG threshold preset: `AA` = 4.5, `AAA` = 7, `AA-large` = 3                                                                             |
| `apcaPreset`   | `'body' \| 'large-text' \| 'ui'`         | `'body'`        | APCA threshold preset used when `metric: 'apca'` and `threshold` is omitted: `body` = 0.6, `large-text` = 0.45, `ui` = 0.3               |
| `apcaPolarity` | `'absolute' \| 'positive' \| 'negative'` | `'absolute'`    | APCA polarity test: `absolute` passes when `abs(Lc) >= threshold`, `positive` when `Lc >= threshold`, `negative` when `Lc <= -threshold` |
| `apcaRole`     | `'sample-text' \| 'sample-background'`   | `'sample-text'` | Whether each sampled color is treated as the text (`Lc = APCA(sample, reference)`) or the background (`Lc = APCA(reference, sample)`)    |

### Sampling options

| Option              | Type                     | Default  | Description                                                                                                                                                                                                            |
| ------------------- | ------------------------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `gamut`             | `'srgb' \| 'display-p3'` | `'srgb'` | Target gamut: the reference and samples are measured as displayed in it, with channels clipped as `contrastRatio` / `contrastAPCA` clip them (an out-of-gamut reference is not gamut-mapped), and paths stay inside it |
| `maxChroma`         | `number`                 | `0.4`    | Upper chroma bound of the region; paths end at this chroma                                                                                                                                                             |
| `alpha`             | `number`                 | `1`      | Alpha channel used while sampling                                                                                                                                                                                      |
| `initialSamples`    | `number`                 | `32`     | Initial samples per gamut chroma extent at the hue (integer `>= 2`, clamped to 512); each contour piece gets a share by its length (at least 1)                                                                        |
| `errorTolerance`    | `number`                 | `0.0015` | Largest distance, in `(l, c)` units, of a sampled midpoint from its chord before the interval is split (`> 0`, clamped to at least `1e-6`)                                                                             |
| `maxDepth`          | `number`                 | `6`      | Maximum halvings of an initial interval to meet `errorTolerance` (integer `>= 0`, clamped to 12); a few more are allowed while a chord leaves the gamut                                                                |
| `simplifyTolerance` | `number`                 | off      | If set, runs Ramer&ndash;Douglas&ndash;Peucker simplification on each path; tolerance in normalized `(l, c)` space, e.g. `0.001`&ndash;`0.002`. Points are kept where a simplified segment would leave the gamut       |

Invalid `initialSamples`, `maxDepth`, or `errorTolerance` values throw an `Error`. `clampContrastRegionSampling(options)` returns the `{ initialSamples, errorTolerance, maxDepth }` the solver runs with (defaults filled in and limits applied, without validating), for example to report the work actually done. Options of removed solvers throw a `TypeError` and are type errors:

- the hybrid solver's `lightnessSteps`, `chromaSteps` (use `initialSamples`), `hybridMaxDepth` (use `maxDepth`), `hybridErrorTolerance` (use `errorTolerance`), and `tolerance` / `maxIterations` (which it forwarded to `maxChromaAt`);
- the legacy marching-squares engine's `engine`, `samplingMode`, `edgeInterpolation`, `adaptiveBaseSteps`, and `adaptiveMaxDepth`.

```ts
// Cheaper settings for interactive overlays (the ContrastRegionLayer defaults).
const paths = contrastRegionPaths(parse('#ffffff'), 220, {
  level: 'AA',
  initialSamples: 8,
  errorTolerance: 0.004,
  maxDepth: 3,
});
```

Solver notes:

- Pass/fail depends only on a sample's displayed luminance (WCAG relative luminance or APCA screen luminance, with channels clipped to the target gamut exactly as `contrastRatio` / `contrastAPCA` clip them), so each side of the region is one level curve. Along a ray from black at the query hue that luminance never decreases inside the gamut, so each side crosses a ray at most once.
- Where a piece starts and ends (on the chroma axis, the gamut edge, `maxChroma`, or the lightness bounds) is found on a fixed internal scan and solved to about `1e-14`, independently of the sampling options. Coarse sampling only coarsens the curve between those ends: it cannot merge, split, or drop pieces, and chords that would leave the gamut are split further.
- Every returned point passes the public check (`contrastRatio` / `contrastAPCA` with the region's gamut) and is in the gamut per `inSrgbGamut` / `inP3Gamut`, including in their `GAMUT_EPSILON` slack (for example the slack sliver near black).
- Gamut notches narrower than the scan (where the edge switches channel bound and back between two scan angles) are found too: next to every edge corner the scan checks one-sided slopes for a turn toward zero. Chords between path points are checked exactly against the gamut (each channel is a cubic along a chord) and split while they leave it.
- Paths are the contrast contour only: they do not run along the gamut edge. They never fold or close, and open paths start at their lower-lightness end. When the threshold equals the contrast against white, only white passes on the light side and it is returned as a one-point path `[{ l: 1, c: 0 }]`.
- The solver has no degraded mode; `inspectPlaneQuery` traces record it as solver `contrast-rays` with the sampling it ran with under `fidelity`, and `droppedPieceCount` counts contour pieces dropped because no end point passed the public checks (0 in every case tested).

## `contrastRegionPath`

Convenience helper that runs `contrastRegionPaths` and returns only the largest detected contour path (or an empty array when no contour exists).

```ts
import { contrastRegionPath, parse } from 'color-kit';

const path = contrastRegionPath(parse('#ffffff'), 220, {
  metric: 'apca',
  apcaPreset: 'large-text',
  gamut: 'display-p3',
});
```

| Parameter   | Type                                   | Default | Description                           |
| ----------- | -------------------------------------- | ------- | ------------------------------------- |
| `reference` | `Color`                                | —       | Reference color                       |
| `hue`       | `number`                               | —       | Fixed hue angle in degrees            |
| `options`   | `ContrastRegionPathOptions` (optional) | `{}`    | Same options as `contrastRegionPaths` |

<p className="api-returns">
  Returns <code>{'ContrastRegionPoint[]'}</code> &mdash; the largest contour
  path, or <code>[]</code>.
</p>
