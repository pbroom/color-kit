# Scale

<p className="docs-lede">
  Interpolation and scale generation in OKLCH space. Build smooth two-color
  ramps or fixed-hue lightness scales with perceptually even steps.
</p>

## Shared Notes

These notes describe the default behavior, when no `options` are passed:

- All interpolation is per-channel linear interpolation of OKLCH components (`l`, `c`, `h`, `alpha`).
- Hue interpolation takes the shortest path around the wheel: when the raw hue difference exceeds 180 degrees, one endpoint is wrapped by 360 before interpolating, and the result is normalized back into `[0, 360)`.
- Near-achromatic endpoints (chroma below `0.001`) do not contribute a hue: the other endpoint's hue is used as-is, and if both endpoints are achromatic the hue is `0`.

## Interpolation options

`interpolate`, `generateScale`, and `mix` accept an optional `InterpolationOptions` object. Passing one switches to CSS Color 4 interpolation, the same math as `color-mix(in <space>, a, b)`. The results match colorjs.io `mix` / `steps` to about 1e-15.

| Option          | Type                                                                   | Default                                          | Description                                                                              |
| --------------- | ---------------------------------------------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `space`         | `'oklch' \| 'oklab' \| 'srgb' \| 'linear-srgb' \| 'p3' \| 'linear-p3'` | `'oklch'`                                        | Space to interpolate in. `linear-srgb` is CSS `srgb-linear`; `p3` is CSS `display-p3`.   |
| `hue`           | `'shorter' \| 'longer' \| 'increasing' \| 'decreasing'`                | `'shorter'`                                      | CSS hue interpolation method. Only used by `oklch`; rectangular spaces have no hue.      |
| `premultiplied` | `boolean`                                                              | `true` for rectangular spaces, `false` for OKLCH | Interpolate with premultiplied alpha, as `color-mix()` does. Hue is never premultiplied. |

How the options behave:

- **Linear light.** `'linear-srgb'` and `'linear-p3'` average light, so the result matches what overlapping lights, blur, or downsampling produce. Its luminance is the average of the endpoints' luminance. Because the two spaces are linear transforms of each other, they give the same result. The red and lime midpoint is `#bcbc00`, compared with `#7f8000` in gamma-encoded `'srgb'` and `#f99500` in OKLCH (the default).
- **Powerless hue.** In `oklch`, an endpoint with chroma at or below `0.000004` (the CSS Color 4 OKLCH epsilon) has a powerless hue and takes the other endpoint's hue. The hue then stays constant along the mix, and no arc is added even with `'longer'`. This is the same as colorjs.io.
- **Alpha.** A fully transparent endpoint contributes no color in rectangular spaces, because alpha is premultiplied. In OKLCH, alpha defaults to straight interpolation so `{ space: 'oklch' }` matches the option-less call for colors with a hue. Pass `premultiplied: true` for full `color-mix()` parity.
- **No gamut mapping.** Mixing in-gamut colors in `srgb` / `linear-srgb` stays in sRGB, and mixing in `p3` / `linear-p3` stays in Display P3. Floating-point noise is clamped away in those cases. Out-of-gamut inputs keep their extended (negative or >1) channel values, so the result can be out of gamut. Mixes in OKLCH (and sometimes OKLab) can leave the gamut even when both inputs are in gamut. Use `toSrgbGamut` / `toP3Gamut` when you need a displayable color.
- **Achromatic threshold.** When `options` are passed, near-achromatic handling uses the CSS threshold (`0.000004`) rather than the `0.001` described in Shared Notes.

## `interpolate`

Interpolates between two colors in OKLCH space. `t = 0` returns the first color, `t = 1` returns the second.

```ts
import { interpolate, parse } from 'color-kit';

const midpoint = interpolate(parse('#3b82f6'), parse('#ef4444'), 0.5);
const viaLight = interpolate(parse('#3b82f6'), parse('#ef4444'), 0.5, {
  space: 'linear-srgb',
});
```

| Parameter | Type                   | Default  | Description                                                                |
| --------- | ---------------------- | -------- | -------------------------------------------------------------------------- |
| `color1`  | `Color`                | required | Start color (returned when `t` is 0).                                      |
| `color2`  | `Color`                | required | End color (returned when `t` is 1).                                        |
| `t`       | `number`               | required | Interpolation position. Values outside 0&ndash;1 extrapolate.              |
| `options` | `InterpolationOptions` | —        | See [Interpolation options](#interpolation-options). Omit for the default. |

<p className="api-returns">
  Returns <code>Color</code> with each channel linearly interpolated and the hue
  normalized into <code>[0, 360)</code>.
</p>

## `generateScale`

Generates an evenly spaced color scale between two endpoints. Both endpoints are included, and each intermediate stop is produced by `interpolate`.

```ts
import { generateScale, parse } from 'color-kit';

const ramp = generateScale(parse('#0f172a'), parse('#f8fafc'), 7);
const lightRamp = generateScale(parse('#ff0000'), parse('#0000ff'), 5, {
  space: 'linear-srgb',
});
```

| Parameter | Type                   | Default  | Description                                                                      |
| --------- | ---------------------- | -------- | -------------------------------------------------------------------------------- |
| `from`    | `Color`                | required | Starting color (first entry in the scale).                                       |
| `to`      | `Color`                | required | Ending color (last entry in the scale).                                          |
| `steps`   | `number`               | required | Number of colors in the scale. Must be at least 2, otherwise an error is thrown. |
| `options` | `InterpolationOptions` | —        | Forwarded to `interpolate` for every stop.                                       |

<p className="api-returns">
  Returns <code>Color[]</code> of length <code>steps</code>, from{' '}
  <code>from</code> to <code>to</code> inclusive.
</p>

## `lightnessScale`

Generates a dark-to-light scale at a fixed hue and chroma. Only lightness varies; chroma, hue, and alpha are copied from the base color.

```ts
import { lightnessScale, parse } from 'color-kit';

const tones = lightnessScale(parse('#3b82f6'), 11, [0.05, 0.95]);
```

| Parameter | Type               | Default        | Description                                                        |
| --------- | ------------------ | -------------- | ------------------------------------------------------------------ |
| `color`   | `Color`            | required       | Base color whose chroma, hue, and alpha are preserved.             |
| `steps`   | `number`           | `11`           | Number of stops. Must be at least 2, otherwise an error is thrown. |
| `range`   | `[number, number]` | `[0.05, 0.95]` | Lightness range as `[min, max]`, interpolated linearly.            |

<p className="api-returns">
  Returns <code>Color[]</code> ordered from the darkest stop (`range[0]`) to the
  lightest stop (`range[1]`).
</p>

<ul className="api-field-list">
  <li>
    <code>l</code> &mdash; evenly spaced between <code>range[0]</code> and{' '}
    <code>range[1]</code>
  </li>
  <li>
    <code>c</code>, <code>h</code>, <code>alpha</code> &mdash; copied unchanged
    from the base color
  </li>
</ul>

Note that stops are not gamut-mapped: high-chroma base colors can produce
out-of-gamut stops at the extremes of the lightness range.
