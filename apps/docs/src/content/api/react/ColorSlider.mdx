## Edge cases

- **The rail is yours.** The slider paints nothing. Sample a rail with
  [`getSliderGradientStyles`](/api/driver/getSliderGradientStyles) and set
  `backgroundImage` to its `activeBackgroundImage` (Display P3) over
  `backgroundColor: srgbBackgroundColor` for older browsers. Sampling from
  the current color makes each rail preview what dragging it would produce.
- **Ranges can run backwards.** The first value of `range` maps to the start
  of the rail (left, or bottom when vertical), so `[1, 0]` puts the maximum
  first. `aria-valuemin` and `aria-valuemax` still report the smaller and
  larger value.
- **Wrapping.** Keyboard steps wrap around the ends for `h` and clamp for the
  other channels; `wrap` overrides either.
- **Thumb inset.** Set the `--ck-slider-position-inset` CSS variable (in px)
  to keep the thumb's center that far from both rail ends, for example half
  the thumb's width so it never overhangs a rounded rail.
- **Children.** The thumb is the slider's first child; markers such as
  [`SliderMarker`](/api/react/SliderMarker) and
  [`ChromaMarkers`](/api/react/ChromaMarkers) render after it, inside the
  rail.
- **Provider or props.** Without a `<Color>` ancestor the slider needs both
  `requested` and `onChangeRequested`; with neither it throws.
