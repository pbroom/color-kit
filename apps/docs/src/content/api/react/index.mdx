`color-kit/react` binds the engine to React state. This page builds
pickers from its hooks, which render no elements themselves: state hooks
that hold a color and share it, and plane hooks that paint a color plane
into your canvas and compute overlay geometry for your SVG. With the hooks,
elements, styles, pointer handling and ARIA are yours. Build them from plain
elements with
[`color-kit/driver`](/api/driver), which holds the picker math (pointer
normalization, keyboard steps, value text), or with your own component
library.

## State: one provider, two hooks

[`Color`](/api/react/Color) holds one color and shares it with every
component inside it. It takes the same options as
[`useColor`](/api/react/useColor), which returns that state with conversions
and setters (`setRequested`, `setChannel`, `setFromString`,
`setActiveGamut`, …) when a provider is more than you need. The provider
itself never re-renders on a color change. In your components,
[`useColorContext`](/api/react/useColorContext) returns the full snapshot and
re-renders on every update;
[`useColorStoreSelector`](/api/react/useColorStoreSelector) subscribes to one
field of the provider's store instead, so a drag re-renders only what depends
on it.

[`useMultiColor`](/api/react/useMultiColor) manages a named collection, such
as a palette or gradient stops, with one selected entry and a display gamut
and view shared by all entries. Its operations build on the latest state, so
several calls in one event handler compose.

## Requested and displayed

Every state keeps two colors apart. `requested` is the exact OKLCH color the
user chose and may sit outside any screen's gamut; it is never clamped.
`displayed` is that color mapped into the active gamut (`'display-p3'` unless
you pass `defaultGamut="srgb"`), and `displayedSrgb` and `displayedP3` hold
both mappings. Place a thumb at the requested color and paint it with the
displayed one, so it never jumps when a color leaves the gamut. The concept
page [Requested vs displayed](/concepts/requested-vs-displayed) explains why.

## Planes: a renderer and geometry hooks

Every plane hook takes the same plane: `{ color, axes }`, where `axes` maps
two OKLCH channels to x and y (lightness across and chroma up by default) and
the third channel comes from `color`. Coordinates are normalized with y
pointing down, so the geometry hooks' path data fits an
`<svg viewBox="0 0 100 100" preserveAspectRatio="none">` laid over the
canvas.

- [`useColorPlaneRenderer`](/api/react/useColorPlaneRenderer) paints the
  plane into a `<canvas>` you render. Attach its `ref` and use its
  `canvasKey` as the canvas `key`. It draws with WebGL, falls back to a CPU
  renderer when WebGL is missing or its context is lost, sizes the backing
  store from the canvas's CSS size and the device pixel ratio, and skips
  redraws that would paint the same pixels.
- [`useGamutBoundary`](/api/react/useGamutBoundary) traces the sRGB or
  Display P3 edge for the plane's hue, and
  [`useChromaBand`](/api/react/useChromaBand) the line the current chroma
  follows across lightness.
- [`useContrastRegion`](/api/react/useContrastRegion) solves the colors that
  reach a WCAG or APCA level against a reference, as contour lines to stroke
  and closed polygons to fill.
- [`useFallbackPoints`](/api/react/useFallbackPoints) places the color after
  gamut mapping into sRGB and into Display P3.

`useGamutBoundary`, `useChromaBand` and `useContrastRegion` return
memoized points plus SVG path data from
[`toSvgPath`](/api/plane/toSvgPath). `useFallbackPoints` returns the `srgb`
and `p3` points, without paths, and `useColorPlaneRenderer` returns a canvas
handle (`ref`, `canvasKey`, the active `renderer`). None of them render
elements.

## Sliders and text

A single channel needs no plane: a native `<input type="range">` already
handles keyboard and ARIA. Paint its rail with
[`getSliderGradientStyles`](/api/driver/getSliderGradientStyles), sampled
from the current color so each rail previews what dragging it would do, and
write with `setChannel`. For text,
[`formatColorStringInputValue`](/api/driver/formatColorStringInputValue) and
[`parseColorStringInputValue`](/api/driver/parseColorStringInputValue)
convert between the color and any CSS color string; commit with
`setFromString`, which keeps the hue of grays. The
[React guide](/guides/react#sliders-and-text) has a live example.

## Controlled or uncontrolled

Uncontrolled, `<Color defaultColor="…">` keeps the state itself. Controlled,
you pass `state` and `onChange`, and the provider only reports updates.
`onChange` fires synchronously inside the setter, once per effective update
and never for a no-op, and the event names the `interaction` (`pointer`,
`keyboard`, `text-input`, `programmatic`) and the `changedChannel`; pass
`interaction` to the setters so it is right. Build the initial state with
[`createColorState`](/api/driver/createColorState).

The [React guide](/guides/react#controlled) has a live controlled
example.

## Contrast regions

[`useContrastRegion`](/api/react/useContrastRegion) outlines the colors of
the current hue that reach a contrast level against a reference, with WCAG 2
or APCA. Stroke `path` for the contour and fill `fillPath` for the passing
area. Pass the fixed background (or text) color as `reference`: without it
the region is measured against the plane's own color. Pick a background and
a level, then drag the thumb in and out of the region.

## Accessibility

The hooks render nothing, so the accessible elements are yours. The driver
supplies the parts a picker needs:

- **Roles and value text.** Give a 2D thumb `role="slider"` with
  `aria-roledescription="2D slider"`, `aria-valuenow` for the x axis and
  `aria-valuetext` from
  [`getColorAreaValueText`](/api/driver/getColorAreaValueText), such as
  "Lightness 60%, Chroma 0.2". For a custom 1D slider,
  [`getColorSliderValueText`](/api/driver/getColorSliderValueText) names the
  channel and unit ("Hue 213°"). Label each with `aria-label`.
- **Keyboard.** [`colorFromColorAreaKey`](/api/driver/colorFromColorAreaKey)
  maps the arrow keys, PageUp/PageDown and Home/End to a new color by a step
  ratio of the range; hue wraps. Focus the thumb on pointer down so a click
  followed by the arrow keys fine-tunes.
- **Canvas and overlays.** Mark the canvas and the overlay SVG
  `aria-hidden`: the thumb carries the value.

## Performance

- [`useAdaptiveQuality`](/api/react/useAdaptiveQuality) lowers a quality
  level while measured frames are slow and raises it when they recover.
  Report each committed drag frame to it and pass its `quality` to the
  renderer (fewer pixels) and the geometry hooks (coarser sampling).
- Pass `isDragging` to the plane hooks: the renderer drops a little
  resolution, and the geometry hooks solve in a shared Web Worker, keeping
  the last result on screen until a fresh one arrives. At rest they solve
  synchronously.
- Moving along an axis channel does not repaint the plane, and the geometry
  hooks key on channel values, so inline `{ color, axes }` objects are free.
- Read single fields with `useColorStoreSelector` rather than
  `useColorContext` in components that re-render often.

The guide [Building with color-kit/react](/guides/react) assembles these parts
into one picker.
