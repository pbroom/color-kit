## The pieces

`color-kit/react` is a thin binding over [`color-kit/driver`](/guides/headless-picker).
Its primitives own behavior and accessibility and ship with no styles; size
and look are yours, through `className`, `style` and `data-*` attributes.

- [`Color`](/api/react/Color) provides shared state to everything inside it.
- [`ColorArea`](/api/react/ColorArea) maps two OKLCH channels to a rectangle
  (lightness by chroma by default). Its children draw:
  [`ColorPlane`](/api/react/ColorPlane) rasterizes the colors, layers such as
  [`GamutBoundaryLayer`](/api/react/GamutBoundaryLayer) and
  [`ContrastRegionLayer`](/api/react/ContrastRegionLayer) draw plane queries
  over it, and one [`Thumb`](/api/react/Thumb) handles keyboard and screen
  readers. A default thumb renders if you omit it.
- [`ColorSlider`](/api/react/ColorSlider) controls one channel: `l`, `c`, `h`
  or `alpha`. Paint its rail with
  [`getSliderGradientStyles`](/api/driver/getSliderGradientStyles) and style
  its thumb through `[data-color-slider-thumb]`.
- [`ColorStringInput`](/api/react/ColorStringInput) shows the requested color
  as text and accepts any CSS color on Enter or blur.

## Uncontrolled

`<Color defaultColor="…">` keeps the state itself. The provider does not
re-render on color changes: each primitive subscribes to the slice it reads,
so a drag re-renders only what depends on it.
[`useColorContext`](/api/react/useColorContext) returns the full snapshot and
setters, and re-renders on every update; for one field, select it from the
store with [`useColorStoreSelector`](/api/react/useColorStoreSelector).

## Controlled

Pass `state` and `onChange` to own the state. `onChange` fires synchronously
inside the setter, once per effective update and never for a no-op. Several
setter calls in one event compose, each building on the last.

```tsx title="controlled.tsx"
import { useState } from 'react';
import { parse } from 'color-kit';
import { createColorState } from 'color-kit/driver';
import { Color, ColorArea, ColorPlane } from 'color-kit/react';

export function ControlledPicker() {
  const [state, setState] = useState(() => createColorState(parse('#3b82f6')));
  return (
    <Color state={state} onChange={(event) => setState(event.next)}>
      <ColorArea style={{ width: 240, height: 160 }}>
        <ColorPlane />
      </ColorArea>
    </Color>
  );
}
```

[`useColor`](/api/react/useColor) takes the same options and returns the
state with its setters (`setChannel`, `setFromString`, `setActiveGamut`, …)
for when a provider is more than you need. The top-level controls,
[`ColorArea`](/api/react/ColorArea), [`ColorSlider`](/api/react/ColorSlider)
and [`ColorStringInput`](/api/react/ColorStringInput), also work on their own
with `requested` and `onChangeRequested` props. Area children such as
`ColorPlane`, `Thumb` and the layers read their state from the surrounding
`ColorArea`, so they always render inside one. For palettes and gradient
stops, [`useMultiColor`](/api/react/useMultiColor) manages named entries with
a shared active gamut.

## The picker

The default color is outside sRGB. The dashed line is the sRGB edge; check
**Preview in sRGB** and the thumb's fill and the displayed readout switch to
the sRGB mapping while the requested color stays put.
