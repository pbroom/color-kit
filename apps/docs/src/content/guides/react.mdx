## The pieces

`color-kit/react` renders nothing. It holds state and computes what a picker
draws; the elements, their styles and their input handling are yours. Build
them from plain HTML with [`color-kit/driver`](/guides/headless-picker),
which holds the picker math, or host them in your own components.

- [`Color`](/api/react/Color) provides shared state to everything inside it;
  [`useColorContext`](/api/react/useColorContext) reads it.
- [`useColorPlaneRenderer`](/api/react/useColorPlaneRenderer) paints a
  two-channel OKLCH plane (lightness by chroma by default) into your
  `<canvas>`, with WebGL and a CPU fallback.
- [`useGamutBoundary`](/api/react/useGamutBoundary),
  [`useChromaBand`](/api/react/useChromaBand),
  [`useContrastRegion`](/api/react/useContrastRegion) and
  [`useFallbackPoints`](/api/react/useFallbackPoints) return overlay geometry
  as points and SVG path data for the same plane.
- [`useAdaptiveQuality`](/api/react/useAdaptiveQuality) trades resolution
  for frame rate while a drag is slow.
- The driver turns input into colors:
  [`createPointerDragController`](/api/driver/createPointerDragController)
  and [`colorFromColorAreaPosition`](/api/driver/colorFromColorAreaPosition)
  for pointers, [`colorFromColorAreaKey`](/api/driver/colorFromColorAreaKey)
  for the keyboard, and
  [`getColorAreaValueText`](/api/driver/getColorAreaValueText) for screen
  readers.

The [API page](/api/react) builds the `PlanePicker` this guide uses, a canvas,
an SVG and a thumb wired to those functions, in one file.

## Uncontrolled

`<Color defaultColor="…">` keeps the state itself. The provider does not
re-render on color changes; [`useColorContext`](/api/react/useColorContext)
returns the full snapshot and setters and re-renders on every update. For one
field, select it from the store with
[`useColorStoreSelector`](/api/react/useColorStoreSelector).

## Controlled

Pass `state` and `onChange` to own the state. `onChange` fires synchronously
inside the setter, once per effective update and never for a no-op. Several
setter calls in one event compose, each building on the last.

```tsx title="controlled.tsx"
import { useState } from 'react';
import { parse } from 'color-kit';
import { createColorState } from 'color-kit/driver';
import { Color, useColorContext, useColorPlaneRenderer } from 'color-kit/react';

function Plane() {
  const { requested } = useColorContext();
  const { ref, canvasKey } = useColorPlaneRenderer({ color: requested });
  return (
    <canvas ref={ref} key={canvasKey} style={{ width: 240, height: 160 }} />
  );
}

export function ControlledPicker() {
  const [state, setState] = useState(() => createColorState(parse('#3b82f6')));
  return (
    <Color state={state} onChange={(event) => setState(event.next)}>
      <Plane />
    </Color>
  );
}
```

[`useColor`](/api/react/useColor) takes the same options and returns the
state with its setters (`setRequested`, `setChannel`, `setFromString`,
`setActiveGamut`, …) for when a provider is more than you need; the plane
hooks only need a color, so they work with either. For palettes and gradient
stops, [`useMultiColor`](/api/react/useMultiColor) manages named entries with
a shared active gamut.

## The picker

The default color is outside sRGB. The dashed line is the sRGB edge; check
**Preview in sRGB** and the plane and the displayed readout switch to the
sRGB mapping while the requested color stays put. The hue slider is a native
range input painted with
[`getSliderGradientStyles`](/api/driver/getSliderGradientStyles).

## Sliders and text

A single channel needs no plane. A native `<input type="range">` already
handles the keyboard and ARIA; paint its rail with
[`getSliderGradientStyles`](/api/driver/getSliderGradientStyles), sampled
from the current color so each rail previews what dragging it would do, and
write with `setChannel`. For text,
[`formatColorStringInputValue`](/api/driver/formatColorStringInputValue) and
[`parseColorStringInputValue`](/api/driver/parseColorStringInputValue)
convert between the color and a CSS color string. Commit with
`setFromString` on Enter or blur, and drop text that does not parse.
